# Автопубликация: Instagram + ВКонтакте по контент-плану

Один пост пишется один раз — и уходит на обе площадки сам, в заданное время.

```
content/plan.yaml  ──▶  планировщик (раз в минуту смотрит, кому пора)
       │                      │
       │                      ├──▶ Instagram Graph API  (reels / фото / карусель)
   content/media/             └──▶ VK API               (стена сообщества)
                                       │
                              content/.state.json — журнал: что уже ушло
                                       │
                              Telegram — уведомление о каждой публикации
```

| Файл                             | Назначение                                             |
| -------------------------------- | ------------------------------------------------------ |
| `content/plan.yaml`              | контент-план: что, когда и куда                        |
| `publish/plan.ts`                | разбор и проверка плана (ошибки ловятся до публикации) |
| `publish/runner.ts`              | ядро: кому пора публиковать, идемпотентность, повторы  |
| `publish/scheduler.ts`           | постоянный режим: проверка плана по таймеру            |
| `publish/platforms/instagram.ts` | Instagram Graph API                                    |
| `publish/platforms/vk.ts`        | VK API                                                 |
| `publish/media.ts`               | публичные ссылки на медиа (нужны Instagram)            |
| `publish/state.ts`               | журнал публикаций — защита от дублей                   |
| `publish/selftest.ts`            | самопроверка всего пути без реальных аккаунтов         |

---

## Быстрый старт

```bash
npm install
cp .env.example .env            # заполняем доступы (разделы ниже)
cp content/plan.example.yaml content/plan.yaml

npm run publish:test            # самопроверка: всё ли собрано правильно
npm run publish:check           # проверить план и доступы
npm run publish:run -- --dry-run  # прогон вхолостую: кто и что получил бы
npm run publish:scheduler       # боевой режим по расписанию
```

Все команды:

| Команда                            | Что делает                                       |
| ---------------------------------- | ------------------------------------------------ |
| `npm run publish:check`            | проверяет план и доступы, печатает расписание    |
| `npm run publish:run`              | публикует всё, чему подошло время, и выходит     |
| `npm run publish:run -- --dry-run` | то же, но без единого запроса в сеть             |
| `npm run publish:cli -- now <id>`  | публикует конкретный пост немедленно             |
| `npm run publish:status`           | журнал: что, куда и когда ушло                   |
| `npm run publish:scheduler`        | постоянный режим (это же запускается на сервере) |
| `npm run publish:test`             | самопроверка на заглушках, без аккаунтов         |

## Шаг 1. Доступы Instagram

Публиковать через API можно **только** в аккаунт Instagram
**Business** или **Creator**, связанный с Facebook-страницей. Личный аккаунт
API не пустит — это ограничение Meta, обойти его нельзя.

1. **Переведи аккаунт в профессиональный.**
   Instagram → Настройки → Тип аккаунта → «Переключиться на профессиональный».
2. **Свяжи с Facebook-страницей.**
   Meta Business Suite → Настройки → Аккаунты → привяжи Instagram к странице
   (страницу можно создать пустую, она нужна как «держатель» доступа).
3. **Создай приложение.**
   [developers.facebook.com](https://developers.facebook.com/apps) → «Создать
   приложение» → тип **Business** → добавь продукт **Instagram**
   (Instagram API setup with Facebook Login).
4. **Получи токен.**
   Открой [Graph API Explorer](https://developers.facebook.com/tools/explorer/),
   выбери своё приложение и запроси разрешения:
   `instagram_basic`, `instagram_content_publish`, `pages_show_list`,
   `pages_read_engagement`, `business_management`.
   Нажми «Generate Access Token».
5. **Сделай токен долгоживущим** (короткий живёт час):
   ```
   GET https://graph.facebook.com/v21.0/oauth/access_token
       ?grant_type=fb_exchange_token
       &client_id=<APP_ID>
       &client_secret=<APP_SECRET>
       &fb_exchange_token=<короткий токен>
   ```
6. **Возьми токен страницы и id инстаграм-аккаунта:**

   ```
   GET https://graph.facebook.com/v21.0/me/accounts?access_token=<длинный токен>
       → id страницы и её access_token  ← это и есть IG_ACCESS_TOKEN

   GET https://graph.facebook.com/v21.0/<id страницы>
       ?fields=instagram_business_account&access_token=<токен страницы>
       → instagram_business_account.id  ← это IG_USER_ID
   ```

```env
IG_USER_ID=17841400000000000
IG_ACCESS_TOKEN=EAAG...
```

> **Про срок жизни.** Токен страницы, полученный из долгоживущего
> пользовательского, не протухает сам, но слетает при смене пароля, отзыве прав
> или через ~60 дней бездействия. Если Instagram вдруг начал отвечать
> «Session has expired» — просто повтори шаги 4–6.

> **Про режим разработки.** Пока приложение в Development mode, публиковать
> можно только в аккаунты, у которых есть роль в приложении (твой — добавь себя
> в «Роли»). Этого достаточно для своих площадок. Публикация в чужие аккаунты
> потребует App Review.

## Шаг 2. Доступы ВКонтакте

1. Сообщество → **Управление** → **Работа с API** → **Ключи доступа** →
   «Создать ключ».
2. Отметь права: **Фотографии**, **Видео**, **Стена** (и «Управление
   сообществом», если планируешь отложенные записи средствами ВК).
3. Скопируй ключ — это `VK_ACCESS_TOKEN`.
4. `VK_GROUP_ID` — числовой id сообщества. Виден в адресе `vk.com/club123456789`
   либо в Управление → Настройки → Адрес страницы.

```env
VK_GROUP_ID=123456789
VK_ACCESS_TOKEN=vk1.a.XXXX
VK_FROM_GROUP=true
```

> **Если ВК отвечает «Access denied: no access to call this method»** —
> у ключа сообщества не хватает прав на загрузку. Возьми **пользовательский**
> ключ администратора сообщества (Implicit Flow, права `photos,video,wall,offline`)
> и положи его в `VK_ACCESS_TOKEN` — остальное работает так же.

> **Клипы.** ВК не даёт публичной документации на загрузку Клипов, и метод
> открыт не всем приложениям. Поэтому по умолчанию вертикальный ролик уходит
> обычным видео с записью на стене. Хочешь попробовать Клипы —
> `VK_CLIPS_FOR_REELS=true`: при ошибке система молча откатится на обычное видео.

## Шаг 3. Где лежат медиафайлы

ВКонтакте принимает файл напрямую. **Instagram — нет:** он скачивает медиа
по ссылке, значит файлу нужен публичный `https://`-адрес. Три варианта:

### `MEDIA_HOST=local` — раздаём сами (проще всего локально и на web-сервисе)

```env
MEDIA_HOST=local
PUBLIC_BASE_URL=https://твой-сервис.onrender.com
MEDIA_PORT=8788
```

Сервис поднимает раздачу на `MEDIA_PORT` и выдаёт Instagram ссылки вида
`https://…/m/<случайный токен>/file.mp4`. Нужен публичный домен: на Render/Railway
это тип **web**, не worker.

### `MEDIA_HOST=s3` — хранилище (надёжнее для сервера без домена)

Подходит Yandex Object Storage, Selectel, MinIO, AWS S3. Бакет может быть
закрытым: ссылка подписывается на час, Instagram успевает скачать.

```env
MEDIA_HOST=s3
S3_ENDPOINT=https://storage.yandexcloud.net
S3_REGION=ru-central1
S3_BUCKET=my-bucket
S3_ACCESS_KEY_ID=...
S3_SECRET_ACCESS_KEY=...
```

### `MEDIA_HOST=none` — ссылки уже в плане

Если файлы и так лежат на сайте — пиши в `media:` прямые `https://`-ссылки.

## Шаг 4. Контент-план

`content/plan.yaml` — обычный текстовый файл, правится в любом редакторе.
Полный пример с комментариями: `content/plan.example.yaml`.

```yaml
timezone: Europe/Moscow

defaults:
  platforms: [instagram, vk]
  tags: [ландшафтныйдизайн]

posts:
  - id: 2026-09-23-terrace-reel # уникальное имя, менять нельзя
    when: 2026-09-23 10:00 # время в поясе timezone
    type: reel # reel | photo | carousel
    media: [media/terrace.mp4]
    cover: media/terrace-cover.jpg
    text: |
      Терраса у воды: собрали за три недели.

  - id: 2026-09-26-carousel
    when: 2026-09-26 18:00
    type: carousel
    media: [media/step-1.jpg, media/step-2.jpg, media/step-3.jpg]
    text: Три шага проектирования участка.
    overrides: # текст можно развести по площадкам
      vk:
        text: Длинная версия для ВК…
        tags: [проектирование]
```

Поля:

| Поле        | Обязательно | Смысл                                                                  |
| ----------- | ----------- | ---------------------------------------------------------------------- |
| `id`        | да          | уникальное имя поста; по нему система помнит, что он уже опубликован   |
| `when`      | да          | `ГГГГ-ММ-ДД ЧЧ:ММ` в поясе `timezone` (или полная дата с `Z`/`+03:00`) |
| `type`      | да          | `reel` (1 видео), `photo` (1 фото), `carousel` (2–10 файлов)           |
| `platforms` | да\*        | `[instagram, vk]`; \*можно задать один раз в `defaults`                |
| `media`     | да          | пути внутри `content/` или готовые `https://`-ссылки                   |
| `cover`     | нет         | обложка для reel                                                       |
| `text`      | да          | текст поста                                                            |
| `tags`      | нет         | хештеги без `#`, добавляются в конец текста                            |
| `overrides` | нет         | свой `text`/`tags` для конкретной площадки                             |

**`id` — это ключ от защиты от дублей.** Поменяешь `id` у опубликованного
поста — система посчитает его новым и выложит второй раз.

## Шаг 5. Проверка перед боем

```bash
npm run publish:check
```

Покажет, какие доступы заданы, и распечатает расписание с отметками, что уже
опубликовано. Ошибки плана (пропавший файл, кривая дата, слишком длинная
подпись) выводятся списком — такие посты не публикуются, остальные уходят.

```bash
npm run publish:run -- --dry-run
```

Полный прогон без единого сетевого запроса: видно, кто и что получил бы.

Первый настоящий пост лучше выпустить руками:

```bash
npm run publish:cli -- now 2026-09-23-terrace-reel
```

## Шаг 6. Сервер (публикует, пока ты занята другим)

Планировщик — обычный процесс. Два варианта:

**Вместе с ботом** (один сервис на всё): `PUBLISH_SCHEDULER_IN_BOT=true` —
бот при старте поднимет и планировщик.

**Отдельным сервисом:** команда запуска `npm run publish:scheduler`.

### Что обязательно настроить на сервере

**Журнал публикаций должен лежать на постоянном диске.** Файловая система
контейнера стирается при каждом передеплое: если журнал потеряется, система
решит, что ничего не публиковала, и выложит посты второй раз.

```env
CONTENT_DIR=/app/data/content
STATE_FILE=/app/data/content/.state.json
```

| Площадка | Где взять постоянный диск                           |
| -------- | --------------------------------------------------- |
| Render   | `render.yaml` уже монтирует диск в `/app/data`      |
| Railway  | Variables → Volumes → примонтировать на `/app/data` |
| Fly.io   | `fly.toml` монтирует том `botdata` в `/app/data`    |

Контент-план и медиа тоже должны быть доступны сервису: либо клади их на тот же
диск (`/app/data/content`), либо коммить `plan.yaml` в репозиторий, а медиа
держи в S3 и ссылайся на них ссылками.

## Что учитывают площадки (проверяется до отправки)

| Ограничение        | Instagram                                    | ВКонтакте              |
| ------------------ | -------------------------------------------- | ---------------------- |
| Длина подписи      | 2200 символов                                | 16 000                 |
| Хештеги            | до 30                                        | не ограничены          |
| Карусель           | 2–10 файлов                                  | вложения одной записью |
| Формат фото        | **JPEG** (png/webp — на свой риск)           | jpg, png               |
| Формат видео       | MP4/MOV, H.264 + AAC, вертикаль 9:16         | mp4, mov и др.         |
| Публикаций в сутки | 50 (лимит Meta, проверяется перед отправкой) | —                      |

Всё, что можно поймать заранее, ловится на `npm run publish:check`.

## Как система защищает от дублей и сбоев

- **Журнал.** После каждой площадки результат сразу пишется в `.state.json`.
  Упал процесс посреди поста — уже опубликованное повторно не уйдёт.
- **Независимые площадки.** Ошибка Instagram не мешает ВК: пост уйдёт туда,
  куда смог, а неудачная площадка попадёт в повтор.
- **Повторы с паузой.** До `PUBLISH_MAX_ATTEMPTS` попыток, пауза растёт
  (5, 10, 15 минут). Исчерпались — приходит уведомление в Telegram.
- **Просроченные посты.** Если сервер лежал сутки, при старте он не вывалит
  весь пропущенный контент разом: публикуются только посты моложе
  `PUBLISH_GRACE_MIN` (по умолчанию 3 часа), остальные помечаются пропущенными.
  Нужно всё-таки выложить — `npm run publish:cli -- now <id>`.

## Частые ошибки

| Сообщение                                                 | Что это значит                                                              |
| --------------------------------------------------------- | --------------------------------------------------------------------------- |
| `Instagram: The user is not an Instagram Business`        | аккаунт не переведён в Business/Creator или не связан со страницей          |
| `Instagram: Session has expired`                          | протух токен — повтори шаги 4–6 первого раздела                             |
| `Instagram: Media type not supported` / `aspect ratio`    | видео не H.264/AAC или нестандартные пропорции                              |
| `Instagram обрабатывает видео дольше N с`                 | большое видео; попытка повторится автоматически                             |
| `ВКонтакте: Access denied: no access to call this method` | ключу сообщества не хватает прав — возьми пользовательский ключ (см. шаг 2) |
| `Для Instagram нужен публичный адрес медиа`               | не задан `PUBLIC_BASE_URL` либо нужен `MEDIA_HOST=s3`                       |
| `файл не найден — media/…`                                | опечатка в пути; пути считаются от папки `content/`                         |

## Чего система пока не делает

- **Stories, IGTV, VK Истории** — только лента, reels/клипы и карусели.
- **Комментарии, ответы, статистику** — только публикация.
- **Дзен, YouTube, Telegram-канал** — не подключены, но добавляются одним
  файлом в `publish/platforms/` (интерфейс `Publisher` в `publish/types.ts`:
  четыре метода, ~100 строк на площадку).
